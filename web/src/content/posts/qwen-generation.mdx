## The Day 5 cache path, unchanged

`generate_cached` didn't need any Qwen-specific code. It calls `forward_cached`, which calls each attention layer's cached path, and those use the same projections, QK-norm and split RoPE as the full forward pass. The only thing that changed is the model it runs.

What does change is the size of the cache. Per token, the cache stores one key and one value for every layer and KV head:

$$
2 \times L \times H_{kv} \times d_{head} \times b
$$

With {q.n_layers} layers, {q.kv_heads} KV heads, {q.head_size} values per head and 2 bytes per float16 value, that's {n(perToken)} bytes per token, {Math.round(perToken / day4)} times the Day 4 model's {n(day4)} bytes per token. A full {n(q.context_length)}-token context would need {(perToken * q.context_length / 2 ** 30).toFixed(1)} GiB for one sequence. Grouped-query attention already halves this. With {q.n_heads} KV heads instead of {q.kv_heads}, every number would double.

<Label>The test</Label>

## Same prompts, same tokens, timed

Each run renders two chat prompts with the native template, warms both paths up, then generates 32 greedy tokens three times with each implementation. It synchronizes CUDA around every timer and reports the median. After timing, it rebuilds the cache and checks that its actual byte count equals the formula.

Two choices keep the comparison fair. Both sides use the same dtype on the same device. And the reference switches from eager attention, which the parity test needed, to SDPA for timing. Timing octlm's SDPA against eager attention would make octlm look faster than it is.

## What counts as a mismatch in float16

The T4 has no BF16 support, so the GPU run uses float16. Two correct float16 implementations can round differently. Over 32 greedy steps, one near tie between the top two candidates can flip a token, and after that the two sequences go their separate ways. Exact equality in float16 partly tests luck.

So before the T4 run, the note changed the stop rule. Float32 still requires exact equality. In float16, a mismatch writes a record of where the sequences split, the reference's gap between its top two logits there, and octlm's logit error at the same spot. The run fails if any logit isn't finite, or if the gap is bigger than the error, since then rounding can't explain the flip.

On the T4, octlm is {Math.round(100 * (1 - ratio(gen(t4)[0])))} and {Math.round(100 * (1 - ratio(gen(t4)[1])))} percent slower than the reference. [The seed-spread post](/blogs/seed-spread-at-scale/) already has a lead on why. PyTorch's documentation says SDPA supports grouped-query attention only in its flash and math kernels on CUDA, and the flash kernel needs a newer GPU than the T4. So octlm's `enable_gqa=True` probably runs the slow math kernel. That's a lead, not a measurement. Decode speed isn't a Day 6 goal, so it stays open. On the CPU octlm is slightly faster, by a margin too small to claim.

<Label>What the output shows</Label>

## The model doesn't know when to stop, the loop does

Look at the generated text. The model answers ("2 + 2 = 4."), emits `<|im_end|>`, and then keeps going. It writes `<|endoftext|>` and invents a new "Human:" turn. That isn't a bug in octlm. The benchmark asks for exactly 32 tokens so both sides do the same work, and nothing tells the loop to stop.

A harness can't work like that. It would read the invented turn as part of the answer. Day 7's loop must stop at `<|im_end|>`, ID {qwen.im_end}, and treat everything before it as the reply.

Decision: keep the Qwen path in `model.py`. All four Day 6 exit checks pass.

<Label>Skipped</Label>

## Not built yet

- **A stop token in the benchmark.** The benchmark keeps its fixed 32 tokens for parity. After Day 6, `generate_cached` accepts stop IDs, and `reply` stops at either end ID listed in the pinned `generation_config.json`, `<|im_end|>` or `<|endoftext|>`.
- **Greedy decoding for the harness.** The [Qwen3-0.6B model card](https://huggingface.co/Qwen/Qwen3-0.6B) warns against greedy decoding in thinking mode because of endless repetition. So the Day 7 harness samples in non-thinking mode with the card's temperature 0.7, top-p 0.8 and top-k 20, and runs each task under several seeds. Greedy decoding stays for parity checks only.
- **Faster GQA on the T4.** Timing `repeat_interleave` keys against `enable_gqa` would test the kernel lead.
