The previous posts built the pieces that turn text into vectors and let positions read each other. A decoder stacks the same block a few times on top of those vectors, and then turns the final vectors back into token scores. Day 1's baseline has two blocks, width 128 and four heads, and it follows the small GPT-2 layout.

<Label>The residual stream</Label>

## Each block adds to the vector, it doesn't replace it

A block doesn't compute a new vector from scratch. It computes a correction and adds it:

$$
x \leftarrow x + \operatorname{Attention}(\operatorname{LN}(x)), \qquad x \leftarrow x + \operatorname{FFN}(\operatorname{LN}(x))
$$

The running vector $x$ is called the residual stream. And the addition actually helps training. The gradient of $x + f(x)$ with respect to $x$ is $1 + f'(x)$, so every block passes at least the identity backward. A deep stack of additions gives the gradient a direct path from the loss to the embedding, and it doesn't shrink as you add more blocks.

<Source file="octlm/model.py" symbol="TransformerBlock" />

The norm sits inside the branch, before attention and before the feed-forward layer. That's called pre-norm. The 2017 paper put it after the addition, which is post-norm, and Day 2 tested that choice in [where the norm goes](/posts/residual-placement/).

<Label>LayerNorm</Label>

## Normalize each vector across its own features

LayerNorm rescales one position's vector to mean 0 and variance 1, then applies a learned gain $\gamma$ and bias $\beta$ per feature:

$$
\operatorname{LN}(x) = \gamma \odot \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta, \qquad \mu = \frac{1}{C}\sum_{i} x_i, \quad \sigma^2 = \frac{1}{C}\sum_i (x_i - \mu)^2
$$

The statistics come from the $C$ features of one vector. They never mix positions or sequences. The Day 1 reading plan made this point on purpose, because BatchNorm, the older method, averages across the batch, and that would make one sequence's statistics depend on another's.

<Figure label="Playground" caption="A six-number vector and its LayerNorm, with gain 1 and bias 0. Use the buttons to shift or scale the input.">
  <NormPlay client:visible initial="layernorm" />
</Figure>

### So what happened ?

- The output always has mean 0 and standard deviation 1, whatever the input is.
- "Add 1 to every entry" leaves the output unchanged, LayerNorm removes any shift.
- "Double every entry" also leaves it unchanged, LayerNorm removes any scale.
- The order of the entries survives. Bigger inputs stay bigger.

Without a norm, activations can grow block by block, and softmax and the feed-forward layer behave differently at different scales. The norm gives every block an input at the same scale. Day 2 compares this with [RMSNorm](/posts/rmsnorm/), which drops the mean.

<Label>Feed-forward</Label>

## A per-position two-layer network

Attention moves information between positions. The feed-forward layer then processes each position alone. It widens the vector to $4C$, applies a nonlinearity, and projects back:

$$
\operatorname{FFN}(x) = W_{\text{down}}\, \operatorname{GELU}(W_{\text{up}}\, x)
$$

For Day 1 that's 128 to 512 and back to 128. The two matrices hold 131,072 parameters per block, twice the attention projections. Most of a Transformer's parameters live here, not in attention, which surprised me the first time.

GELU is basically a smooth ReLU. It weights each input by the probability that a standard normal variable is below it, $\operatorname{GELU}(x) = x \cdot \Phi(x)$. Big positive inputs pass through, big negative ones go to 0, and near 0 the curve is smooth and dips a bit below zero.

<Label>The output head</Label>

## Tied weights, the embedding read backwards

The head turns each final vector into $V$ scores. octlm uses the embedding matrix for this, transposed:

$$
z = h\, E^\top, \qquad z \in \mathbb{R}^{V}
$$

The score for token $v$ is the dot product between the final hidden vector and that token's embedding row. So the model predicts token $v$ when its output vector points the same way as $v$'s input vector. One matrix does both ends, which saves $V \times C$ parameters, 131,072 at Day 1 size and 4.2 million at Day 4 size, and gives rare tokens' rows a gradient from both directions. In code it's one line, `self.lm_head.weight = self.token_embedding.weight`.

<Label>EXP-007</Label>

## The bug that stopped the model from learning

Problem, the first test run of the baseline learned really poorly. The test that overfits one block failed.

The cause was the initialization. PyTorch's `nn.Embedding` draws its weights from a standard normal, $\sigma = 1$. As an input that's fine, because the first LayerNorm rescales it. But with a tied head, the same rows are also the output weights. The final hidden vector has entries around unit size after the last norm, and its dot product with a row of $C$ unit-variance numbers has a standard deviation of about $\sqrt{C} \approx 11$. Softmax over scores that far apart puts nearly all the probability on one random token.

<Figure label="Playground" caption="The expected loss of a fresh model with a tied head at each initial weight scale. A model that knows nothing should start at ln V.">
  <InitScale client:visible />
</Figure>

### So what happened ?

- At $\sigma = 1$ the top token takes most of the probability and the starting loss is way above $\ln V$. The model starts confident and wrong, and its first job is to undo that.
- At $\sigma = 0.02$ the scores spread by about 0.23, the distribution is nearly uniform, and the loss starts at $\ln V$.

The fix draws every linear and embedding weight from $\mathcal{N}(0, 0.02^2)$, the GPT-2 value, and sets biases to zero. The overfit test passed after that. Decision, keep.

Per block, attention holds $4C^2 = 65{,}536$ weights, the feed-forward layer $8C^2 = 131{,}072$, and the two norms $4C = 512$. The linear layers have no biases. The token table adds $VC$, the position table $T_{\max}C$, and the final norm $2C$.

<Label>Skipped</Label>

## What we didn't build, and why

- **Biases on the linear layers.** octlm follows current decoders and uses none. The norms keep their bias on Day 1 because PyTorch's `LayerNorm` has one.
- **Dropout.** The layers accept it and every config sets it to 0. These models are undertrained, not overfit.
- **Scaled init for residual projections.** GPT-2 also shrinks the output projections by $1/\sqrt{2L}$. At two layers the difference is small, and the change would need its own comparison.
